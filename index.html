LIS-03 / SCHEMA
03 — Schema definition

Schema

Every table with its primary key, foreign keys, and remaining columns — the plain-language contract behind the SQL.

PATIENT
PKpatient_id
—first_name VARCHAR(50)
—last_name VARCHAR(50)
—date_of_birth DATE
—gender ENUM
—contact_number VARCHAR(20)
—address VARCHAR(255)
—email VARCHAR(100)
DOCTOR
PKdoctor_id
—first_name VARCHAR(50)
—last_name VARCHAR(50)
—specialization VARCHAR(100)
—contact_number VARCHAR(20)
—email VARCHAR(100)
STAFF
PKstaff_id
—first_name VARCHAR(50)
—last_name VARCHAR(50)
—role ENUM
—contact_number VARCHAR(20)
—username VARCHAR(50) UNIQUE
—password_hash VARCHAR(255)
TEST_CATALOG
PKtest_id
—test_name VARCHAR(100)
—test_category VARCHAR(50)
—specimen_type VARCHAR(50)
—price DECIMAL(10,2)
—turnaround_hours INT
—normal_range VARCHAR(100)
—unit VARCHAR(20)
LAB_ORDER
PKorder_id
FKpatient_id → PATIENT
FKdoctor_id → DOCTOR
—order_date DATETIME
—status ENUM
—priority ENUM
ORDER_TEST
PKorder_test_id
FKorder_id → LAB_ORDER
FKtest_id → TEST_CATALOG
—status ENUM
SPECIMEN
PKspecimen_id
FKorder_test_id → ORDER_TEST (UNIQUE)
FKcollected_by → STAFF
—specimen_type VARCHAR(50)
—collection_date DATETIME
—status ENUM
TEST_RESULT
PKresult_id
FKspecimen_id → SPECIMEN (UNIQUE)
FKverified_by → STAFF
—result_value VARCHAR(100)
—unit VARCHAR(20)
—reference_range VARCHAR(100)
—flag ENUM
—result_date DATETIME
—remarks VARCHAR(255)

What each section is used for, and why it was included in this package.

Cover material

          
Sets the scope up front — what system this is, what engine it targets, and what's included — so the package can be handed off without a verbal walkthrough.

        

      

      

        
02

        

          
ER diagram

          
Created first because every other artifact derives from it. It fixes the entities and cardinalities before a single CREATE TABLE is written, catching design mistakes while they're still cheap to change.

        

      

      

        
03

Used as the bridge between the diagram and the code — a plain-language contract listing every column, type, and key so a reviewer can sanity-check the design without reading SQL.

The buildable artifact. Everything above exists to justify what's in this file — it's the only piece that actually creates the database.
